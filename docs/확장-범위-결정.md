# 확장 범위 결정 — 어디까지 만들고 어디서 멈추는가

2026-08-09 기록.

이 문서는 "T-record를 학급 교육과정 전반을 다루는 도구로 넓힐 것인가"에 대한 판단과
그 근거를 남긴다. 나중에 같은 유혹이 다시 왔을 때 처음부터 다시 재지 않기 위한 기록이다.

## 한 줄 결론

**넓히지 않는다.** 교육과정 편성(연간 진도·시수·주간계획)은 영구히 포기하고,
관찰이 문장이 되는 줄기(수업 설계 → 관찰 기록 → 생기부 문장)만 더 판다.
확장의 생사는 아래 G2 게이트 하나에서 갈린다.

## 무엇과 비교했나

초등 담임교사용 상용 데스크톱 프로그램(교육과정 작성 계열)과 사슬 다섯 칸에서 맞대 봤다.

| 사슬 | 판정 | 근거 |
|---|---|---|
| ① 교육과정 — 연간 편성·시수·진도 | **상대 압승** | 저쪽 코드·데이터의 최대 비중이 여기다. 따라가려면 매년 수만 행 규모의 콘텐츠를 다시 굽는 공장이 필요하다 |
| ② 평가계획 | **상대 우세** | 완성된 평가과제를 골라 쓰게 해 준다. 다만 **콘텐츠로 이기는 것이지 구조로 이기는 게 아니다** — 계획서 *내보내기*만 얹으면 실무 격차는 좁혀진다 |
| ③ 수업 설계 — 지도안 | **T-record 승 (부전승)** | 상대에는 지도안·수업자료 제작 기능이 아예 없다 |
| ④ 관찰 기록 | **T-record 승** | 상대는 날짜×학생 자유 텍스트 장부. 이쪽은 근거유형·성취기준 태그·산출물 사진·수준이 붙은 구조화된 증거 |
| ⑤ 생기부 문장 | **T-record 승** | 상대는 성취기준별 기성 문장을 고르는 방식이고 기재요령 검사가 없다 |

3:2로 이기는 그림이 아니다. **상대가 이기는 ①②는 교사가 실제로 돈을 내는 칸이고,
이쪽이 이기는 ③④⑤는 수요가 검증되지 않은 칸이다.** 이 비대칭을 잊지 말 것.

## 구조적 차별점 — 상대가 원해도 못 따라오는 것

### 1. 관찰 → 문장 연결

상대는 ④(누가기록)와 ⑤(문장)를 **둘 다 갖고 있으면서 서로 잇지 않았다.**
누락이 아니라 구조적 불가능이다 — 연결을 만드는 순간, 성취기준별 기성 문장 코퍼스라는
자기 최대 자산의 존재 이유가 사라진다. 혁신가의 딜레마가 제품 구조에 박제돼 있다.

교사에게의 실이득은 **문장의 방어 가능성**이다. 민원·정정 요청이 왔을 때
기성 문장 사용자는 "골랐다"고밖에 답할 수 없고, 이쪽 사용자는
날짜·근거유형·산출물이 달린 관찰 목록을 내놓는다.

### 2. 콘텐츠 무의존 = 갱신 부채 0

상대의 유지비는 매년 수만 행, 교육과정 개정기에는 수십만 셀이다.
그 부채는 이미 사용자 화면에까지 새어 나오고 있다(빈 칸에 "업데이트될 예정입니다"가 남아 있다).

T-record의 외부 데이터는 성취기준(교육부 고시)뿐이다. 교과서가 바뀌어도,
검정 출판사가 몇 종으로 늘어도 다시 구울 것이 없다.
**1인 개발자가 지속 가능한 유일한 위치가 여기다.** 이것을 잃는 결정은 어떤 것도 하지 않는다.

무료·웹·설치 없음은 차별점이 아니다. 유통 편의지 기능 우위가 아니며,
상대 사용자는 이미 돈을 내고 있다 — 가격은 진입장벽이 아니었다.

## 정직성 불변식과의 관계

코드 주석에 못 박아 둔 설계 불변식 25개를 확장안과 하나씩 맞대 봤다.
**뒤집어야 하는 것은 0개다.** 15개는 무관, 8개는 오히려 확장의 안전장치가 된다
(성장 판정 한계, 결석·미제출 분리, '이상 없음' 금지, AI 게이트 리셋, 교사 값 우선,
루브릭 관문, 저장하지 않기로 한 것들).

특히 다음 셋은 확장 압력이 가장 세게 붙는 자리이므로 못을 다시 박는다.

- **`app.src.html` "시기는 자유 한 줄로 묶는다 — 차시·주간계획 구조로 번지지 않게"**
  — 지킨다. 시기를 월·주로 구조화해 학기 격자를 얹자는 안이 한 번 나왔고 **기각했다.**
  격자를 얹는 순간 "시수는? 진도는?"이 따라오고 그 끝이 콘텐츠 공장이다.
  단, **관찰 날짜 소급 입력은 이 불변식과 무관하다** — 시기 계획이 아니라 기록 사실의 정확성 문제다.
- **"성취기준 전수 커버리지 표는 만들지 않는다(초등은 전 기준 평가 의무가 없다)"**
  — 지킨다. 조건 하나: 평가계획서 내보내기는 **만든 과제만** 나열한다.
  빈 기준을 함께 보여주는 순간 커버리지 표로 변질된다.
- **"활동지·수업자료 파일은 만들지 않는다 — 만드는 법을 프롬프트로 알려 주는 데까지만"**
  — 지킨다. 상대에게 수업 설계 기능이 없다는 사실이 확인됐어도,
  이 결정의 근거(브라우저가 A4·OOXML을 직접 그리는 길의 품질 상한, 교육청 배포 실물 조사)는
  하나도 흔들리지 않았다. **지도안만으로 이미 부전승**이라 상한 낮은 산출물로 승수를 늘릴 이유가 없다.

## 실행 순서

### Phase 0 — 신뢰 기반 수리 (무조건, 확장을 접더라도 한다)

- **관찰 날짜 소급 입력·수정.** 지금은 생성 시 오늘 날짜로 고정되고 고칠 방법이 없다.
  교사는 금요일에 월~목 관찰을 몰아 적는데, 그러면 날짜가 전부 거짓이 된다.
  "문장 뒤에 날짜 있는 근거"가 이 도구의 상품인데 그 상품이 자기모순에 빠져 있다.
  **편의 기능이 아니라 정직성 버그다.**
- 저장 유실 창 봉합 — 디바운스 저장만 있고 이탈 시 flush가 없다.
- 학생 삭제 시 `task.targets`의 죽은 id 정리.
- localStorage 쓰기 실패·용량 초과 감지와 백업 유도.
- 공용 프록시 주소 하드코딩을 설정으로 분리.
- 스키마 마이그레이션 골격(현재는 읽는 자리 방어 호환뿐).
- 죽은 필드 정리, `notAssessed`·`reflect`는 입력 UI를 주거나 인쇄에서 뺀다.

**완료 판정**: 입력 직후 탭 강제 종료 → 재열기에서 마지막 입력 보존, 10회 전수 통과.
과거 날짜 관찰의 생성·수정·CSV 반영 확인. 학생 삭제 후 유령 id 0건.
이전 백업 JSON을 새 코드로 가져와 무손실.

### Phase 1 — 학교 제출용 평가계획서 내보내기 (HWPX)

데이터가 **이미 전부 있는** 유일한 제출 문서다. 신규 입력 없이 3월 제출물이 나온다.
교사가 도구를 여는 계절적 이유를 만드는 것이 목적이다.

**완료 판정**: 본인 학교 실제 양식으로 결재 통과 1건 + 타 학교 양식 2종에서 한글 편집 10분 이내로 맞춰짐.
**중단 판정**: 학교 양식 3종 표본에서 공통 표가 안 나오면 HWPX 표 출력을 접고
붙여넣기용 구조화 텍스트로 격하한다(병합셀 취약은 이미 아는 한계다).

### Phase 2 — 학기말 작업대 (④→⑤ 연결 심화) · **결정적 게이트**

학생 한 명의 전 관찰을 축·근거유형·과제별로 시간순 **나열**하고
(집계가 아니라 나열이다 — 학생 단위 집계 금지 불변식) 거기서 바로 초안 → 검사 → 게이트로 잇는다.
관찰 없는 축은 채우지 않고 "없음"으로 둔다. 판정·세션은 저장하지 않는다.
스키마 무변경이 목표다.

**완료 판정**: 본인 학급 전원의 생기부 서술을 T-record만으로 완료(한글 빈 문서에서 시작하지 않고).
**중단 판정**: 본인이 학기말에 한글+기억으로 회귀하면 여기서 확장 전체를 접는다.

### Phase 3 — 단원(다차시) 설계 · Phase 2 통과 시에만

과제 하나에 차시 배열을 허용한다. **날짜·주차는 넣지 않는다.**
루브릭 관문은 유지하고, 산출물은 지도안 다차시 확장까지만.

**중단 판정**: 두 단원 이내에 "결국 한글에서 다시 짰다"가 나오면 접는다.

## 만들지 않기로 한 것

| 안 만드는 것 | 이유 |
|---|---|
| 연간 편성·진도표·시수 집계·주간학습안내·월중행사·창체 편성 | 상대의 본진이고, 진입하는 순간 갱신 부채를 상속받는다 |
| 교과서·차시 데이터 일체 | 매년 죽는 데이터. 저작권도 겹친다 |
| 활동지·PPT·학습지 파일 생성 | 품질 상한이 낮다. 프롬프트 제공을 유지한다 |
| 지필 성적·석차·성적표 | 채점 매트릭스 금지 계열 불변식 전면 위반 경로 |
| 문장 은행·예시 문장 콘텐츠 | 콘텐츠 무의존이라는 차별점의 자살이고, 상대의 약점(전국 동일 문장)을 수입하는 짓이다 |
| 시기의 월·주 구조화, 학기 격자 | 검토했고 기각했다. 위 불변식 참조 |

## Go / No-Go

| 게이트 | 진행 | 중단 |
|---|---|---|
| G0 (Phase 0) | — 무조건 수행 | — |
| G1 (Phase 1 후) | 본인 학교 결재 통과 + 동료 교사 1명 이상이 자기 계획서를 뽑아 씀 | 양식 파편화로 텍스트 격하조차 쓸 수 없다는 판정 |
| **G2 (Phase 2)** | **한 학기 동안 학생당 관찰 평균 3건 이상을 실제로 담고, 학기말 생기부 서술 전원을 이 도구만으로 완료** | 학기말에 한글+기억으로 회귀. 이때는 Phase 3 이하를 전부 접고 현행 범위의 완성도 유지 모드로 전환한다 |
| G3 (공개 후 1학기) | 백업 JSON을 다시 가져와 이어 쓰는 사용자가 존재 | 내려받기만 있고 이어 쓰기 0 |

**핵심은 G2다.** 기준을 "남이 쓸 것 같은가"가 아니라 **"내가 실제로 썼는가의 전수 기록"**으로 둔다.

## 가장 강한 반대 논거 (지우지 말 것)

상대 프로그램이 오래 팔린 이유는 노동을 **줄여** 주기 때문이다.
T-record는 노동을 **요구**한다 — 평소에 관찰을 담아야 학기말에 뭐가 나온다.
"더 정직한 노동"이 "더 적은 노동"을 시장에서 이긴 적은 드물다.

③④⑤에서 이긴다는 판정은 **품질 기준이지 수요 기준이 아니다.**
성공 시나리오가 전부 "교사들이 기록 습관을 바꾼다"에 걸려 있고,
행동 변화를 전제하는 도구의 기저 성공률은 낮다.

이 논거를 반증하는 유일한 증거가 G2다. 그래서 게이트를 거기 뒀다.

## 외부 자료 활용 방침

상용 프로그램을 분석해 설계 판단에 쓴 것은 사적 참고에 그친다.

**하지 않는 것**

- 상대의 평가과제·루브릭·생기부 문장·진도표·설문 문항 등 **텍스트 자산을 어떤 형태로도 들이지 않는다.**
  환언·재작성·AI 재생성은 2차적저작물이라 해법이 아니고, 선택·배열(편집저작물)까지 권리가 미친다.
  진도표 계열은 교과서 출판사 권리가 하나 더 얹힌다.
- 상대의 DB 스키마·필드명을 모방하지 않는다. 얻는 것 없이 유래의 흔적만 남는다.
- 분석 부산물(덤프·스키마·추출 문자열)을 이 저장소에 커밋하지 않는다.
  이슈·커밋 메시지에도 상대 제품의 내부 구조를 적지 않는다.

**하는 것 — 텍스트를 규칙으로 증발시키고 원문은 폐기한다**

아이디어·사실·방법은 보호 대상이 아니다. 산출물에 남는 것은 정규식과 임계값이지 문장이 아니다.

- 루브릭 코퍼스의 **작성 문법**(수준 간 무엇이 달라지는가 — 정도부사·조건·자립도, 서술 길이 분포,
  금기 패턴)을 통계로 뽑아 `rubricLint` 규칙을 보강한다.
- 생기부 문장 코퍼스의 **문형 통계**(명사형 종결 형태, 매듭 구조, 주어 회피)로
  기재요령 검사와 초안 프롬프트를 보강한다.
- **평가방법 분류 체계**(구술·발표 / 서답형 / 서술·논술형 등)는 교육부 평가 용어이므로
  `task`의 축으로 채택한다. 근거유형(기재요령 5종)과는 다른 축이다 — 근거유형은 무엇을 보고 썼는가,
  평가방법은 어떻게 쟀는가.
- 성취기준당 평가과제가 몇 갈래로 갈리는지 같은 **분포 사실**은 설계 판단 근거로만 쓴다.

원문 파일은 저장소 밖에 두고, 규칙을 뽑은 뒤 폐기한다.
